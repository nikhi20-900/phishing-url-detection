## 2. Corrections (verified discrepancies)

### 2.1 Report §5.2 SHAP table is not reproducible from the committed pipeline

The original report's local-attribution table for the single external false negative (`https://www.gonoconlatarjetaverde.com.mx/`, P(Phish) = 0.15) lists:

| Report §5.2 claims | Recomputed & stored values (`external_validation_results.json`) |
| :--- | :--- |
| `URLLength` −0.1342 | *not in top-5* |
| `IsHTTPS` −0.1287 | `IsHTTPS` −0.1290 |
| `NoOfEqualsInURL` −0.0984 | `NoOfOtherSpecialCharsInURL` **+0.1244** |
| `NoOfQMarkInURL` −0.0751 | `NoOfDegitsInURL` −0.0792 |
| `DomainLength` **+0.1620** | `DegitRatioInURL` −0.0647 |

Fresh execution with the frozen model artifact and the committed SHAP verification path (`compute_shap_explanation`, including the additive-consistency check that base + ΣSHAP = 0.149999… ≈ 0.15) reproduces the **right-hand column** stored in the JSON:

```
IsHTTPS                    = 1.0   shap = -0.1290
NoOfOtherSpecialCharsInURL = 3.0   shap = +0.1244
NoOfDegitsInURL            = 0.0   shap = -0.0792
DegitRatioInURL            = 0.0   shap = -0.0647
TLDLength                  = 2.0   shap = -0.0531
```

The report's table therefore appears to have been transcribed from an earlier or different computation and does **not** match the machine-readable artifact or a deterministic re-run. The qualitative narrative (TLS and his absence of query parameters push toward legitimate) remains supported, but `DomainLength` is **not** a top-5 phishing-pushing attribution for this case in the reproducible numbers.

**Impact:** interpretive accuracy of one feature-attribution table; headline metrics unaffected.

### 2.2 Consolidated benchmark was not built by the committed loaders

The shipped `external_validation_benchmark.csv` cannot be regenerated by the pre-audit code:

| Property | `load_phishtank_feed` output | Shipped benchmark CSV |
| :--- | :--- | :--- |
| PhishTank `source_id` | `PHISHTANK-<id>` | bare `<id>` (all 247 rows) |
| `verification_method` | `community_vote_and_analyst_verified` | `phishtank_community_verified` |
| PhishTank row count | 249 (all `verified=yes`, `online=yes`) | 247 |

The 2 missing rows are the cross-feed duplicate URLs also present in OpenPhish; they were silently deduplicated and re-attributed to OpenPhish. `url`, `label`, and `source` content are otherwise stable.

**Fix implemented:** new deterministic `build_external_benchmark()` (explicit feed-priority deduplication) reproduces the shipped benchmark's `url/label/source` sequences exactly (verified by execution) while emitting schema-consistent provenance columns; it refuses to overwrite existing snapshots unless `overwrite=True`.

### 2.3 Hardcoded "N=1,047" in pipeline output

`run_external_validation` printed a hardcoded sample size regardless of input; replaced with dynamic counts.

## 3. Registered-Domain Granularity Caveat (overlap audit)

`extract_registered_domain` uses a hard-coded two-part public-suffix list that does not cover every ccTLD (e.g., Bangladesh `.com.bd`). Unlisted two-part suffixes collapse to the suffix itself:

```
extract_registered_domain('https://shop.com.bd/a') -> 'com.bd'
```

Consequences: the phishing slice's "registered domain overlap 36/241 (14.94%)" can slightly overstate distinct-infrastructure overlap (one benchmark URL resolves to the generic `com.bd` bucket that also appears in PhiUSIIL). This has **no effect on evaluation metrics** (domain grouping is not used in scoring) and changing the suffix list would alter the frozen Phase 3 split reproduction, so it is documented rather than modified.

## 4. Dataset Provenance & Independence Limitations (unchangeable from this repo)

1. **URL-level independence: verified.** Zero exact-URL (and case-insensitive) overlap against PhiUSIIL (235,370 unique URLs, captured 2024); external feeds captured 2026-10-30/31 — no training-row leakage path.
2. **Domain-level dependence: real and disclosed.** The legitimate slice (Curated-Authoritative) shares registered domains with PhiUSIIL (70.67%) and hostnames (42.86%), so the model may have memorized per-domain lexical regularities. The phishing slice shares hosting platforms on 36 registered domains (14.94%).
3. **Benchmark design is a targeted stress test, not a population sample.** The 500 legitimate URLs were intentionally constructed with deep paths/query strings; the 94.0% FPR quantifies behavior on structured deep links and cannot be generalized to unweighted web traffic. The original report discloses this (§7.4).
4. **Collection scripts not committed.** The snapshot capture process (how/where the OpenPhish text feed, PhishTank CSV, and curated corpus were obtained and filtered) is reproducible only up to the file level; capture tooling is absent. See `data/external/README.md`.
5. **Licensing/usage terms not verifiable from the repository.** OpenPhish Community Feed and PhishTank each define their own usage terms; no license grant for redistribution of these snapshots is included.

## 5. Threshold Sensitivity (fixed-threshold vs. tunable numbers)

All headline recall/FPR numbers are evaluated at the fixed decision threshold τ = 0.5 (Θ frozen artifact). Recomputed sweep on the combined benchmark (phishing | FP among 500 legit | legitimate recall):

| τ | Phishing recall | FPs (legit flagged) | Legitimate recall |
| ---: | ---: | ---: | ---: |
| 0.05 | 1.0000 | 485 | 0.0300 |
| 0.10 | 1.0000 | 481 | 0.0380 |
| 0.15 | 1.0000 | 481 | 0.0380 |
| 0.20 | 0.9982 | 480 | 0.0400 |
| 0.30 | 0.9982 | 480 | 0.0400 |
| **0.50** | **0.9982** | **470** | **0.0600** |
| 0.80 | 0.9835 | 450 | 0.1000 |
| 0.90 | 0.9671 | 420 | 0.1600 |
| 0.95 | 0.9616 | 378 | 0.2440 |

Interpretation (data-supported only):
- The single external false negative (τ=0.50, P=0.15) would be eliminated at τ ≤ 0.15 with 481 FPs instead of 470 — phishing catch and false-alarm counts are **weakly traded off** here.
- The benign false-alarm problem is largely **high-confidence** (FPs sit at P(Phish) 0.95–0.96 per §6.2 of the original report; the sweep FPs remain ≥ 378 even at τ = 0.95): threshold tuning cannot resolve the covariate-shift failure.
